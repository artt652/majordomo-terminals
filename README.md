# majordomo-terminals

Доработки модуля «Терминалы» MajorDoMo. В репозитории лежат только изменённые и новые файлы, в той же структуре каталогов, что и в [sergejey/majordomo](https://github.com/sergejey/majordomo). Основа — ветка alpha, коммит `290ca35`.

## Очередь сообщений

- **Только для дополнений, которые её просят.** Работает для дополнений с методом `useQueue()`, возвращающим true: mediaplayer и pipup. Остальные дополнения работают как раньше.
- **Сообщения не перебивают друг друга.** На одном терминале сообщения звучат по очереди, разные терминалы говорят параллельно. Очередь разбирается отложенными заданиями (`setTimeOut`), отдельного цикла нет.
- **Срочные идут первыми.** Это `ask` и уровень ≥ 9. Срочное прерывает обычное сообщение, а если звучит другое срочное, ждёт его конца.
- **Повторы склеиваются.** Та же фраза второй раз не ставится, а готовый звуковой файл фразы присоединяется к её записи.
- **Плеер восстанавливается.** Перед первым сообщением серии сохраняется, что играл плеер, после последнего тот же трек включается с той же позиции. Если трек остался в плейлисте под тем же номером (vlcweb), он включается через `pl_play`, и плейлист сохраняется; сообщения из плейлиста удаляются. Если плеер заменил плейлист (mpd, lms) или плейлиста нет, файл запускается заново.
- **Конец сообщения по плееру.** Конец сообщения считается по длине файла (резерв). Если дополнение умеет `isPlaying()` (mediaplayer и все `*_tts`) и плеер к этому времени ещё играет сообщение, следующее ждёт, проверка каждые 2 с, не дольше 30 с.
- **Громкость сообщений.** Поле «Громкость сообщений» у mediaplayer и всех `*_tts` (1–100): перед сообщениями плеер переключается на неё, после — на прежнюю, даже если музыка не играла. Работает, если плеер сообщает свою громкость. У pipup — громкость звука окна относительно громкости устройства.
- **Старые сообщения удаляются.** Не проигрываются сообщения старше 10 минут. Сторож (`MINUTELY`) перезапускает застрявшую очередь, `startup` сбрасывает её.

## Настройки дополнений

Дополнение TTS (`modules/terminals/tts/`) и дополнение плеера (`modules/app_player/addons/`) объявляют поля карточки терминала методом `settingsFields()`:

```php
function settingsFields()
{
    return array(
        array('NAME' => 'PORT', 'TITLE' => 'Порт PiPup', 'HINT' => 'пусто — 7979'),
        array('NAME' => 'VOICE', 'TITLE' => 'Голос', 'TYPE' => 'combo', 'OPTIONS' => array('' => 'Любой', 'device' => 'Устройство')),
    );
}
```

- `TYPE`: `text` (по умолчанию), `password`, `number`, `select`, `combo` (список подсказок, можно ввести своё), `checkbox`; ещё `DEFAULT`, `HINT`, `OPTIONS`.
- Все значения хранятся в JSON-полях `TTS_SETTINGS` / `PLAYER_SETTINGS` отдельно для каждого дополнения: у каждого плеера и каждого TTS свои, смена типа их не стирает. Поля плеера с именами прежних столбцов (`PLAYER_PORT`, `PLAYER_USERNAME`, `PLAYER_PASSWORD`, `PLAYER_CONTROL_ADDRESS`) при сохранении ещё и копируются в эти столбцы, значениями выбранного плеера, поэтому дополнения `app_player` работают без изменений.
- У дополнения TTS может быть описание (свойство `$description`); оно показывается под выбором типа TTS, как у плееров.
- Дополнение читает свои значения через `terminalsAddonSettings($this->terminal, 'tts' или 'player', 'имя_дополнения')`.
- Плеер без `settingsFields()` получает прежний набор: порт, имя пользователя, пароль. TTS без него полей не получает.

## Тип TTS для терминала

| Плеер терминала | Тип TTS |
|---|---|
| VLC (HTTP), другие плееры | `mediaplayer` |
| MPD | `mpd_tts` |
| Logitech Media Server | `lms_tts` |
| Kodi | `kodi_tts` |
| Chromecast | `chromecast_tts` |
| DLNA | `dnla_tts` |

После замены файлов переустановите модуль «Терминалы», чтобы создались таблицы и подписки на события.

Совместимо с PHP 7 и 8.
