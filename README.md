# majordomo-terminals — ветка `alpha`

Минимальные доработки модуля «Терминалы» MajorDoMo поверх [sergejey/majordomo](https://github.com/sergejey/majordomo), ветка `alpha`. В репозитории лежат только изменённые и новые файлы, в той же структуре каталогов.

Эта ветка — то, что нужно другим модулям от «Терминалов», и ничего сверх этого: очередь сообщений, настройки дополнений, общие функции и события. Мессенджер «Сообщения» — отдельный модуль [artt652/majordomo-messages](https://github.com/artt652/majordomo-messages) , камеры — модуль [artt652/majordomo-go2rtc](https://github.com/artt652/majordomo-go2rtc); PiPup — отдельно (переносится). Полная версия со всем этим вместе — ветка `main` (коммит `01d6e2b`, 24.10.2026).

## Очередь сообщений

- **Только для дополнений, которые её просят** (`useQueue()` возвращает true; сейчас — `mediaplayer`). Остальные работают как раньше.
- **Полосы.** Голос, звуки и голосовые — полоса `voice`, ролики — `video`, картинки и текст без озвучки — `image`, камеры — `camera`. В полосе — по очереди, разные терминалы — параллельно. Очередь разбирает отложенное задание (`setTimeOut`), отдельного цикла нет.
- **Правила между полосами** (пришло ↓ / звучит или показывается →):

  | | Музыка | Ролик | Голос | Картинка | Камера |
  |---|---|---|---|---|---|
  | **Ролик** | пауза → возврат | по очереди | ждёт конца | ждёт | ждёт |
  | **Голос** | пауза → возврат | пауза → возврат | по очереди | одновременно* | одновременно* |
  | **Картинка** | играет дальше | пауза → возврат* | одновременно* | по очереди | ждёт* |
  | **Камера** | пауза → возврат | пауза → возврат | одновременно* | ждёт* | по очереди |

  \* — если устройство умеет показывать одновременно (объявляет пару в `queueLanes()`), иначе голос останавливает картинку и камеру, а они ждут голос; картинка и камера ждут друг друга. Остановленное после запускается заново: ролик — с начала, камера — снова. Музыка возвращается, когда в полосах, которые её останавливают, ничего не осталось.
- **Полосы устройства** объявляет дополнение (`queueLanes()`, см. ниже). Без него — одна полоса на всё, как раньше; только текст без озвучки не держит голос.
- **Срочные** (`ask` и уровень ≥ 9) звучащее не прерывают: идут следующими, раньше обычных; между собой — по порядку.
- **Сигнал перед сообщением** звучит перед голосом, только если голос до этого молчал (20 с).
- **Повторы склеиваются.** Та же фраза второй раз не ставится, готовый файл голоса присоединяется к своей записи. Повтор той же камеры продлевает её окно.
- **Плеер восстанавливается.** Перед первой записью серии сохраняется, что играло (`saveState()`), после последней — включается с того же места (`restoreState()`).
- **Команды плееру во время сообщений** (кнопки плеера, сценарии, `playMedia()`) сообщения не прерывают: `play` с файлом — это и включится после сообщений (ролик — в очередь полосы `video`, если терминал показывает видео); `pause` / `play` — включать ли музыку после; `stop` — музыку не возвращать; громкость — после; `next`, `previous`, `seek`, действия с плейлистом — после возврата; `status` и остальные запросы — сразу. Ответ app_player — `success`, сообщение `queued`.
- **Конец сообщения** — по длине файла; если дополнение умеет `isPlaying()`, ожидание продлевается, пока плеер ещё играет сообщение.
- **Громкость сообщений и сигнал перед сообщением** — поля `mediaplayer`.
- **Картинка и отправитель.** Картинка из `say('… image:cms/путь.jpg', уровень)` и поля `image` / `from` события `SAYTO` идут с сообщением; их показывает дополнение с `showMessage()`.
- **Текст без озвучки** (`terminalSay(…, $silent = true)`) голос не задерживает.
- **Выключенные устройства не ждём**: перед обращением — проверка порта устройства (не дольше 1 с, адрес даёт `deviceAddress()` дополнения); не ответило — 60 с к нему не обращаемся.
- **Старые сообщения** (старше 10 минут) не проигрываются; сторож (`MINUTELY`) перезапускает застрявшую очередь, `startup` сбрасывает «занято».
- **Журнал** (`cms/debmes/<дата>/terminals.log`) — с адресами устройств; пароли, ключи и подписи в ссылках скрываются.

## Голос терминала

Поле «Голос» в карточке терминала (`TTS_ENGINE`) — какой модуль синтеза речи озвучивает его сообщения, если их несколько (например, кухня — sanotts, MAIN — Яндекс).

- **Пусто** — любой, как раньше.
- **Имя модуля** — терминал играет только файлы этого модуля из `SAY_CACHED_READY`. Кто сделал файл, «Терминалы» узнают из поля события `tts_engine` (yandex_tts: `yandex_tts_v3` подходит к `yandex_tts`) или `tts` (sanotts).
- **Модуль, который о себе не сообщает**, — его файлы играют, как раньше, на всех терминалах, в том числе с выбранным голосом.
- Подсказки в поле — модули, которые уже присылали файлы голоса с полем о себе; можно вписать и своё.

Чтобы генераторы не делали лишних файлов, им предлагается спрашивать «Терминалы» перед синтезом, а после синтеза ставить `ignoreVoice` вместо `BREAK` (`BREAK` обрывает событие и для остальных подписчиков):

```php
if (function_exists('terminalsVoiceNeeded')) {
    if (!terminalsVoiceNeeded('sanotts', $event, $details)) return;   // фраза не нужна ни одному терминалу
} elseif (!empty($details['ignoreVoice'])) {
    return;                                                           // старые «Терминалы»: как раньше
}
// … синтез, SAY_CACHED_READY с 'tts_engine' => 'sanotts' …
$details['ignoreVoice'] = true;
```

`terminalsVoiceNeeded($engine, $event, $details)` — да, если среди терминалов-адресатов (`SAY` — все, кто говорит; `SAYTO` / `ASK` — `destination`) есть выбравший этот модуль или терминал без выбранного голоса, а фразу ещё никто не озвучил (`ignoreVoice`). Нет терминалов-адресатов — как раньше: только если `ignoreVoice` не стоит.

## Для других модулей и сценариев

Версия возможностей — константа `TERMINALS_API` (сейчас 1). Модуль, которому нужна очередь или события, проверяет её (`defined('TERMINALS_API')`) и со старыми «Терминалами» работает в урезанном виде.

**Отправка на терминал**
- `terminalSay($terminal_rec, $message, $level, $image = '', $sender = '', $ref = 0, $silent = false)` — метод класса `terminals`.
- Событие `SAYTO` принимает необязательные поля `image`, `from` и `ref` — метка записи вызывающего модуля: номер или «модуль:номер» (`app_messages:15`). С именем модуля подписчик `TERMINAL_DELIVERED` отличает свои записи от чужих.
- `terminalsQueueCall($terminal, $method, $args, $options)` — метод дополнения через очередь (для сценариев). Общие методы: `sendImage`, `sendSound`, `sendWebImage`, `sendVideo`; дополнение может объявить свои методом `queueMethods()`. `$options`: `level`, `busy` (сколько секунд полоса занята), `lane` (полоса, если не подходит выбранная по методу: `sendImage` / `sendWebImage` — картинка, `sendVideo` — ролик, поток (`rtsp://…` или тип `stream`) — камера, остальное — голос), `refs` (метки записей).

  ```php
  include_once(DIR_MODULES . 'terminals/terminals.class.php');
  terminalsQueueCall('Кухня', 'sendImage', array('cms/cached/snapshot.jpg', 'Звонок в дверь'));
  ```
- `terminalsFind($name)` — терминал по имени, названию или адресу; `terminalsMinLevel($terminal_rec)` — его минимальный уровень сообщений.

**События** (подписка — `subscribeToEvent('мой_модуль', 'TERMINAL_DELIVERED')`):

| Событие | Когда | Поля |
|---|---|---|
| `TERMINAL_DELIVERED` | сообщение с меткой записи отдано устройству | `terminal`, `terminal_id`, `refs` — метки через запятую (номера или «модуль:номер») |
| `TERMINAL_RENAMED` | терминал переименован в карточке | `old`, `new`, `terminal_id` |
| `TERMINAL_DELETED` | терминал удалён | `terminal`, `terminal_id` |

**Необязательные методы дополнения TTS** (проверяются через `method_exists`, базовый `tts_addon.class.php` не меняется): `useQueue`, `queueLanes`, `stopLane`, `saveState` / `restoreState`, `isPlaying`, `showMessage`, `playFile`, `sendVideo`, `canShowVideo`, `deviceAddress`, `queueMethods`, `settingsFields`.

Полосы устройства — `queueLanes()`: список полос и пары, которые оно показывает одновременно. Полоса, которой нет в списке, идёт в `voice`; картинки, если их полосы нет, ничего не ждут.

```php
// один плеер (mediaplayer): всё по очереди, голос останавливает ролик и камеру
function queueLanes() { return array('voice', 'video', 'camera'); }

// окно поверх экрана (как PiPup): картинка — поверх ролика и камеры, голос — с картинкой и камерой
function queueLanes()
{
    return array('voice', 'image', 'video', 'camera',
        'parallel' => array('voice+image', 'voice+camera', 'image+video', 'image+camera'));
}
```

`stopLane($lane)` — убрать с экрана остановленную полосу (вызывается перед тем, что её останавливает). Команды, которые дополнение само отправляет плееру во время сообщений, очередь не задерживает: перед ними — `terminalsPlayerDirect(true)`, после — прежнее значение (`mediaplayer` делает то же в своём `playerCommand()`).

## Настройки дополнений

Дополнение TTS (`modules/terminals/tts/`) и дополнение плеера (`modules/app_player/addons/`) объявляют поля карточки терминала методом `settingsFields()`:

```php
function settingsFields()
{
    return array(
        array('NAME' => 'PORT', 'TITLE' => 'Порт', 'HINT' => 'пусто — 7979'),
        array('NAME' => 'VOICE', 'TITLE' => 'Голос', 'TYPE' => 'combo', 'OPTIONS' => array('' => 'Любой', 'device' => 'Устройство')),
    );
}
```

- `TYPE`: `text` (по умолчанию), `password`, `number`, `select`, `combo` (подсказки, можно ввести своё), `checkbox`; ещё `DEFAULT`, `HINT`, `OPTIONS`.
- Значения хранятся в `TTS_SETTINGS` / `PLAYER_SETTINGS` отдельно для каждого дополнения: смена типа их не стирает. Поля плеера с именами прежних столбцов (`PLAYER_PORT`, `PLAYER_USERNAME`, `PLAYER_PASSWORD`, `PLAYER_CONTROL_ADDRESS`) копируются и в столбцы — дополнения `app_player` читают их как раньше.
- Дополнение читает свои значения через `terminalsAddonSettings($this->terminal, 'tts' или 'player', 'имя_дополнения')`.
- Плеер без `settingsFields()` получает прежний набор: порт, имя пользователя, пароль. TTS без него полей не получает. Описание типа TTS — свойство `$description`.

## Тип TTS `mediaplayer`

Особенности плеера `mediaplayer` учитывает сам, по типу плеера терминала:

| Плеер терминала | Что делает mediaplayer |
|---|---|
| VLC (HTTP) и другие | сообщение — запуском файла; трек остался в плейлисте под тем же номером — возврат через `pl_play` |
| MPD (проверено на MPD 0.23) | сообщение добавляется в конец плейлиста — плейлист сохраняется; позиция трека в статусе MPD учтена |
| Logitech Media Server, Kodi | как MPD (не проверено на устройствах) |
| Chromecast | прежний трек загружается сразу с позиции (не проверено) |
| DLNA | wav перекодируется в mp3, нужен ffmpeg (не проверено) |

Сообщения, ролики и камеры `mediaplayer` отправляет плееру командой напрямую, а не через `playMedia()` (иначе очередь приняла бы их за команды пользователя), поэтому хук `playMedia` из настроек к ним не применяется.

Видео и потоки (`sendVideo()`, через очередь) — у плееров с экраном (VLC, Kodi, Chromecast, DLNA — только mp4), с галочкой «Показывать видео». Поле «Камеры»: RTSP или HTTP MP4 (для VLC без live555, Chromecast, DLNA).

## Установка

Скопировать файлы поверх MajorDoMo (ветка `alpha`) и переустановить модуль «Терминалы»: создадутся таблицы `terminals_queue`, `terminals_state`, поля `TTS_SETTINGS`, `PLAYER_SETTINGS`, `TTS_ENGINE` и подписки на `MINUTELY` и `startup`; у прежней `terminals_queue` добавятся поля `LANE`, `PAUSED`, `CHECKS`. Существующие поля не меняются.

Совместимо с PHP 7 и 8.
